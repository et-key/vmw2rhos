# 実装状況

更新日: 2026-10-09

## 第一段階: ローカル移行計画

Python標準ライブラリーでローカルHTTPサーバーとSQLite保存を実装した。
外部パッケージやクラスタなしで、表の編集と移行計画のチェックを試せる。

| 設計項目 | 実装状況 |
| --- | --- |
| 構成の収集 | JSON取り込み。CLIでvSphereのVM基本情報とAffinity収集。実環境接続は未検証 |
| 編集表 | VM、領域、NIC、配置、例外、共通対応を編集可能 |
| 共通対応 | フォルダー→Namespace、接続元→ネットワーク、領域元→StorageClassの完全一致 |
| 個別指定 | 共通対応より優先。競合する共通対応は検出 |
| データ保存 | schema_version=1のJSON、SQLiteへの計画版保存 |
| 差分 | 取り込み前の編集差分と、移行元・計画・移行先実測の3列比較。計画識別子で古い実測を判定 |
| 一括変更 | 選択行の同一項目へ一括適用 |
| ストレージ | 領域ごとの接続、共有関係、容量、方式、整合性手順の計画 |
| ネットワーク | NIC、VLAN、接続先、MAC・IP方針の計画 |
| Affinity | VM同士・VM–ホストグループを収集。元の属性とグループ構成を保持。自動変換は未実装 |
| OS更新等 | 種類、工程、実行定義の参照、成功判定の編集。実行は未実装 |
| 依存関係 | 移行順序の生成、参照欠落・循環の検出 |
| 事前チェック | 入力整合性のみ。実環境の能力・権限・到達性は未検証 |
| Warm/Cold | 計画上の選択。実方式の対応判定・転送は未実装 |
| 自動実行・復旧 | 未実装。実行APIは公開せず、計画のexecutableは常にfalse |
| 利用者管理 | ローカル単独利用。認証、役割、変更者の監査は未実装 |
| CSV | 未実装。まずJSONを正本として扱う |

「確認済み」は利用者が入力した構成・方針に対する確認であり、ライブ検証の代替ではない。
不足情報や手動対応を理由付きで検出し、ローカルチェックの成功と実行可能状態を区別する。

## 次の段階

1. vSphere収集のディスク・NICへの拡張とスナップショット、再収集時の変更・個別指定保持。
2. OpenShift収集アダプターと接続・権限・ネットワーク・ストレージ能力のライブ検証。
3. 製品バージョン・OS・Warm/Coldの対応表とAffinity変換。
4. 移行基盤アダプター、計画版固定、永続的な工程管理と外部状態照合。
5. 例外処理、切替・検証・復旧と実環境での受入検証。

実環境アダプターは対象製品の仕様を確認してから実装する。表の入力だけで実転送やOS更新を開始しない。

差分とAffinity収集の仕様・制限は [追加設計](comparison-and-affinity.md) に記載する。
